# Recheck capabilities and expose readiness gaps

**All 60 evaluated routes were rechecked against current primary documentation on 16 November 2026, but they are not all ready to use.** The proposals identify **59 official routes and one third-party route**, Stape’s Google Tag Manager connection. Their availability classifications are **42 available, eight beta, three preview, five restricted and two unverified**. Of 300 action cells, **35 remain unverified across 18 entries**; another 20 explicitly depend on configuration or permissions. Meta and The Trade Desk now have accessible current documentation, replacing their old blanket pending assessments with specific capabilities and restrictions. RudderStack remains pending and should show no current grade. **No route was authenticated or live-tested in this audit.** These counts describe the five research JSON proposals, not a deployed website or a guarantee that every account can use the documented features.

## Official status does not establish operational readiness

Provenance answers who maintains the evaluated connection. Availability answers whether that particular route is released, beta, restricted or unconfirmed. Setup describes the remaining installation, administration and integration work. These dimensions cannot be collapsed into a single Ready badge. A vendor’s available REST API still requires a custom AI integration, while a hosted MCP can require an administrator, a paid plan or a private invitation. The proposed catalogue contains **14 native-app routes, 27 hosted MCP routes, ten self-managed routes and nine custom API routes**. Stape’s MCP performs documented GTM writes, but is operated by Stape rather than Google. Supermetrics, Zapier and Pipedream are official implementations of their own products; their connections to other platforms are not native connectors maintained by those platforms. ([Stape repository](https://github.com/stape-io/google-tag-manager-mcp-server), [Supermetrics write access](https://docs.supermetrics.com/docs/how-to-enable-campaign-write-access), [Zapier MCP](https://docs.zapier.com/mcp/home), [Pipedream MCP](https://pipedream.com/docs/connect/mcp))

“Available” is the audit’s classification for a documented, obtainable implementation without an unresolved route-wide release label. It does not assert that the vendor issued a formal general-availability announcement, nor establish entitlement, regional availability, compatibility or reliability for a specific account. The retained editorial readiness data classify **24 routes as Production, 33 as Test and three as Research**. Here Production remains a documentation-based assessment, not an execution receipt. An unresolved action can still exist within an otherwise available route, as with Canva publishing or Mixpanel’s distinct publishing action. Those gaps must remain next to the action, even if the grade is high. ([Canva connector actions](https://www.canva.com/help/mcp-canva-usage/), [Mixpanel tools and limitations](https://docs.mixpanel.com/docs/mcp))

## Fresh evidence changes five grades and several action boundaries

**Meta moves from B− to B+.** Its official hosted MCP documents campaign, ad-set and ad creation, updates and explicit activation; new objects start paused. Deletion is Partial because audience and catalogue-object deletion does not establish campaign deletion. Its accessible current pages do not confirm general rollout, and some creative formats have limited availability. The capabilities can therefore be scored while availability stays visibly unverified and readiness remains Test. Official Markdown documentation resolved the earlier HTML access failure. The CLI is separately documented, but its broader commands were not borrowed to improve the MCP assessment. ([Meta campaign tools](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-ad-creation-and-management.md), [Meta setup](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-get-started.md), [Meta CLI](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-cli/ads-cli-overview.md))

**The Trade Desk moves from B to C+** for the OAK capability that is currently established: useful reads. Its release table marks data retrieval and reporting Available, while configuration remains dated H2 2026 despite write-oriented examples elsewhere. A date window and examples do not prove shipment. Its four write action cells remain Unverified, with closed-beta access explicit. **Reddit moves from C to C+** because its official v3 schema establishes campaign status updates including ACTIVE and DELETED, while effective delivery still depends on approval and billing. This remains a custom API integration. ([OAK capabilities](https://open.thetradedesk.com/advertiser/docsApp/AdvertiserNews/news/doc/McpOpenAgenticKitOverview), [OAK closed-beta setup](https://open.thetradedesk.com/advertiser/docsApp/Foundations/resources/doc/McpOpenAgenticKitGettingStarted), [Reddit OpenAPI schema](https://ads-api.reddit.com/api/v3/openapi.json))

**Ahrefs moves from C+ to B** because official API + MCP labels now establish project creation, modification and deletion. Those writes do not edit a website, and some keyword operations remain API-only. **Make moves from B+ to B** because exact creation, deletion and activation tools remain unverified despite documented scenario execution and scoped management. These five changes are editorial judgements under the existing read/write/setup rubric, not measured performance scores. Pinterest’s announced MCP remains forthcoming; its operational assessment stays on the API. ## Keep uncertainty precise instead of removing it

The proposed data contain **151 Yes, 52 Partial, 42 No, 35 Unverified and 20 Depends** action cells. Partial means a documented object or operation boundary; Depends means configured tools or permissions determine the result; Unverified means the reviewed evidence did not establish the operation. Neither conditional nor unknown is a promise. The 18 entries with at least one Unverified cell are TikTok, Campaign Manager 360, The Trade Desk, Mixpanel, DataForSEO, Adobe Analytics, Adobe CJA, Meridian, Robyn, PyMC-Marketing, RudderStack, Canva, Adjust, Segment, Runway, Similarweb, Make and Workato. Several other entries have specific unknown sub-actions inside a Partial category, such as Meta campaign deletion and Sanity published-document deletion. The five-slot table is therefore a summary, not an exhaustive statement of every platform feature. ([Meta tool scope](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-ad-creation-and-management.md), [Sanity authoring MCP](https://www.sanity.io/docs/ai/mcp-server))

The main evidence tensions are explicit. OAK’s release table and write examples disagree about shipment. Workato lists a China endpoint but separately excludes China in its availability statement; the record conservatively preserves the exclusion. Canva’s plan wording varies by feature, so the record retains a feature-specific entitlement warning. dbt’s Beta flag concerns its OAuth path, while token access remains available; Robyn’s Beta flag concerns Python, while R has a stable release. Databricks evaluates SQL MCP Beta alone, without borrowing the separate Genie One service’s GA status. Sanity document validation and Mixpanel experiment/flag tools have beta qualifications even though their core routes are available. A single route-wide availability label cannot replace these specific notes. ([OAK](https://open.thetradedesk.com/advertiser/docsApp/AdvertiserNews/news/doc/McpOpenAgenticKitOverview), [Workato availability](https://docs.workato.com/en/mcp/developer-api-mcp), [Canva setup](https://www.canva.com/help/mcp-agent-setup/), [dbt authentication](https://docs.getdbt.com/docs/dbt-ai/setup-remote-mcp), [Robyn Python](https://facebookexperimental.github.io/Robyn/docs/robyn-api/), [Databricks SQL](https://docs.databricks.com/aws/en/agents/mcp-tools/databricks-sql), [Sanity](https://www.sanity.io/docs/ai/mcp-server), [Mixpanel](https://docs.mixpanel.com/docs/mcp))

The audit rechecked the **60 named evaluated routes and their five action categories**, with ancillary CLI/plugin facts updated where the evidence specifically covered them. It is not a certification of every alternative integration, every endpoint, or every inherited interface field. Source access failures were resolved through vendor Markdown, released source code or other official pages where possible. TikTok’s separate exact tool library remained unreadable; missing delete/activation evidence stays flagged. RudderStack’s public documentation still does not establish release maturity or a complete write inventory. No connector was installed, no account authenticated and no live write executed. ([TikTok capability guide](https://ads.tiktok.com/resources/help/article/about-tiktok-for-business-mcp-server?lang=en), [TikTok tool library](https://business-api.tiktok.com/portal/docs/available-tools-in-tiktok-for-business-mcp-server/v1.3), [RudderStack documentation](https://mcp.rudderstack.com/docs))

Publication should preserve those boundaries in both languages: show the named route, ownership, availability flag and setup burden before the details; retain action-specific uncertainty; place the dated evidence with descriptive source links. A historical grade should never survive as a current recommendation when essential evidence is pending. The website still needs source integration, schema/build checks and rendered verification before this research can be described as implemented or live.

The evidence set consists of the five reviewed record files and their cited notes in `research_notes/Official capability audit/`. Counts were computed across those 60 unique IDs against the committed catalogue; all 60 records retain documentation-only evidence. This report synthesises the researchers’ fresh primary-source checks and does not add an independent live test.
