# Contributing

Corrections and additions are welcome.

## Before opening a pull request

1. Use an official source wherever possible.
2. Explain whether the interface is official, community-maintained, beta, preview, or restricted.
3. Confirm whether it is read-only, read/write, mixed, or not stated.
4. Update `verifiedOn`.
5. Run `npm run build` and `npm run check`.

## Rating changes

Capability facts and editorial ratings are intentionally separate. A proposed rating change must explain:

1. what changed in the daily workflow;
2. whether readiness should be Production, Test or Research;
3. why the current grade is no longer fair; and
4. which positive or negative should be added, removed or rewritten.

Keep each list to five points or fewer. A vendor announcement alone does not establish production readiness.

Please do not submit referral links, copied vendor copy, client information, credentials, or unverified promotional claims.
